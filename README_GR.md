# CHRYSPHARMACY v2.4 — Υπενθυμίσεις φαρμάκων & μετρήσεις υγείας

Νέα έκδοση βασισμένη στη v2.3. **Διατηρεί το ίδιο CSS**, διαχειριστή, πελάτες, συνταγές, μηνύματα, SMS.to, email και push. Περιλαμβάνει δύο νέες λειτουργίες:

1. **Υπενθυμίσεις λήψης:** Δημιουργία/επεξεργασία/παύση από admin ή τον συνδεδεμένο πελάτη, με όνομα φαρμάκου, οδηγίες, ώρα (ζώνη Europe/Athens), έναρξη/λήξη, επιλογή Portal/SMS/Email/Push και ημερήσιο ιστορικό ανά κανάλι. Μπορούν να καταχωριστούν περισσότερες υπενθυμίσεις σε διαφορετικές ώρες για το ίδιο φάρμακο. Η ώρα αποτελεί υπενθύμιση, **όχι επιβεβαίωση λήψης**.
2. **Πίεση/σάκχαρο:** Ο πελάτης καταχωρίζει ημερομηνία, μεγάλη/μικρή πίεση από 5 έως 25 ανά 0,5 (αποθήκευση σε mmHg: π.χ. 12,5 = 125 mmHg), σάκχαρο 60–500 mg/dL ανά 1, βλέπει ιστορικό και μπορεί κατόπιν ρητής επιβεβαίωσης να στείλει CSV με τις μετρήσεις μέσω email. Ο admin έχει προβολή, όχι καταχώριση ή εξαγωγή αντί του πελάτη.

## Α. Σημαντικό: Backup PostgreSQL

Η αναβάθμιση είναι σχεδιασμένη **χωρίς διαγραφή υπαρχόντων εγγραφών**, αλλά πάρε πλήρες backup πριν αλλάξεις οτιδήποτε. Χρησιμοποίησε τα πραγματικά όνομα βάσης και username του υπάρχοντος `.env` (μην τα δημοσιεύεις):

```bash
mkdir -p ~/Documents/farmakeio/backups
chmod 700 ~/Documents/farmakeio/backups
pg_dump -h 127.0.0.1 -U Ο_ΧΡΗΣΤΗΣ_ΒΑΣΗΣ -d Η_ΒΑΣΗ_ΣΟΥ -Fc \
  -f ~/Documents/farmakeio/backups/chryspharmacy_pre_v24.dump
chmod 600 ~/Documents/farmakeio/backups/chryspharmacy_pre_v24.dump
ls -lh ~/Documents/farmakeio/backups/chryspharmacy_pre_v24.dump
```

Μην βάζεις κωδικό PostgreSQL στο shell history. **Μην ανεβάζεις αυτό το backup σε δημόσια υπηρεσία**, καθώς περιέχει προσωπικά δεδομένα υγείας και ΑΜΚΑ.

## Β. Εγκατάσταση στο Raspberry Pi

Σταμάτα την τρέχουσα εφαρμογή. Κάνε αποσυμπίεση στον φάκελο `~/Documents/farmakeio` ώστε να προκύψει `~/Documents/farmakeio/chryspharmacy_v2_4`:

```bash
cd ~/Documents/farmakeio/chryspharmacy_v2_4
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp ../farmakeio1/.env .env
chmod 600 .env
```

Αν το `.env` είναι σε άλλη θέση, προσαρμόζεις τη διαδρομή του `cp` — **μην αντικαταστήσεις το υπάρχον αρχείο `.env`** και μη δημιουργήσεις νέα βάση. Έλεγξε ιδιαίτερα `DATABASE_URL`, `SECRET_KEY`, `SMS_ENABLED`, `SMS_TO_API_KEY`, `EMAIL_ENABLED`, `SMTP_*` και τις `VAPID_*` ρυθμίσεις. Αν χρησιμοποιείς τοπικά SSL αρχεία σε παλιό φάκελο, αντέγραψέ τα προστατευμένα ή χρησιμοποίησε τις σωστές απόλυτες διαδρομές.

## Γ. Αναβάθμιση PostgreSQL (v2.3 → v2.4)

**Μόνο αφού είσαι σίγουρος ότι το `.env` δείχνει τη σωστή υπάρχουσα βάση** και έχεις backup:

```bash
cd ~/Documents/farmakeio/chryspharmacy_v2_4
source .venv/bin/activate
python -m flask --app app:create_app upgrade-v24
```

Εναλλακτικά από `psql` με κατάλληλη σύνδεση: `\i migrations/003_reminders_measurements_v24.sql`. Μην κάνεις και τα δύο. Η migration δημιουργεί μόνο:
- `medication_reminders`
- `medication_reminder_deliveries` (μοναδικός συνδυασμός υπενθύμιση–ημέρα–κανάλι για περιορισμό διπλής αποστολής)
- `health_measurements`

Δεν εκτελείται `DROP` και δεν αλλάζουν οι υπάρχοντες πίνακες. Η migration χρησιμοποιεί PostgreSQL (δεν ενδείκνυται για SQLite). Αν έρχεσαι από έκδοση *πριν τη v2.3*, ολοκλήρωσε πρώτα την `upgrade-v23`, με το αντίστοιχο backup.

## Δ. Εκκίνηση & νέες σελίδες

Για **τοπική δοκιμή HTTPS** με ήδη εγκατεστημένα/έμπιστα mkcert πιστοποιητικά (μόνο δικές σου συσκευές):

```bash
python -m flask --app app:create_app run --host 0.0.0.0 --port 5001 \
```

- Πελάτης: `/client/medications` και `/client/health` από τις νέες κάρτες της προσωπικής καρτέλας.

## Ε. **ΑΠΑΡΑΙΤΗΤΟ:** Αυτόματες υπενθυμίσεις από cron

Οι υπενθυμίσεις **δεν στέλνονται από μόνες τους με την απλή εκκίνηση Flask**. Ο προγραμματισμένος έλεγχος πρέπει να καλείται από cron σε σταθερή συχνότητα. Χρησιμοποιεί **ώρα Ελλάδας** με `Europe/Athens` ακόμη και αν το σύστημα έχει άλλη ζώνη. Κάθε εκτέλεση εξετάζει τις υπενθυμίσεις των τελευταίων 10 λεπτών (και μετρά μέγιστο μία προσπάθεια ανά ημέρα και κανάλι).

Δοκίμασε αρχικά **χωρίς αποστολή και χωρίς εγγραφή logs**:

```bash
cd ~/Documents/farmakeio/chryspharmacy_v2_4
source .venv/bin/activate
python -m flask --app app:create_app send-medication-reminders --dry-run
```

Για πραγματική εκτέλεση:

```bash
python -m flask --app app:create_app send-medication-reminders
```

Κατόπιν εγκατάστησε cron για **κάθε λεπτό** (επιλέγοντας απόλυτη διαδρομή στο νέο φάκελο):

```bash
crontab -e
```

Πρόσθεσε **μία** γραμμή:

```cron
* * * * * cd /home/takis/Documents/farmakeio/chryspharmacy_v2_4 && /home/takis/Documents/farmakeio/chryspharmacy_v2_4/.venv/bin/python -m flask --app app:create_app send-medication-reminders >> /home/takis/Documents/farmakeio/chryspharmacy_v2_4/reminders-cron.log 2>&1
```

Έλεγξε ότι η ώρα αναγνωρίζεται, η εντολή έχει δικαιώματα στη βάση και ότι τα logs δεν περιέχουν ευαίσθητες πληροφορίες. **Απενεργοποίησε τυχόν παλιούς cron jobs για υπενθυμίσεις** για αποφυγή διπλών εργασιών. Υπενθυμίσεις δεν εξασφαλίζουν ακρίβεια δευτερολέπτου ή παράδοση: εξαρτώνται από λειτουργία του Raspberry Pi, δικτύου και υπηρεσιών. Αν είναι offline για περισσότερο από το παράθυρο των 10 λεπτών, η υπενθύμιση χάνεται εκείνη την ημέρα. Για ιατρικά κρίσιμη δοσολογία μην βασίζεσαι αποκλειστικά σε αυτό το σύστημα.

## ΣΤ. Κανάλια και συναίνεση

- **Portal:** δημιουργεί μήνυμα στην προσωπική καρτέλα πελάτη (χρειάζεται login για προβολή).
- **SMS.to:** απαιτεί `SMS_ENABLED=true`, πραγματικό `SMS_TO_API_KEY`, έγκυρο κινητό και κατάλληλη συναίνεση SMS.
- **Email:** απαιτεί `EMAIL_ENABLED=true`, σωστές `SMTP_*` ρυθμίσεις και συναίνεση email.
- **Push:** απαιτεί VAPID κλειδιά, εγγεγραμμένη συσκευή και HTTPS που **εμπιστεύεται ο browser**. Μπορεί να παραμένει ανενεργό ώσπου να επιλυθεί η τοπική δοκιμή Service Worker.

SMS, email και push χρησιμοποιούν **γενικό μήνυμα** χωρίς ΑΜΚΑ, όνομα φαρμάκου ή δοσολογία· το portal εμφανίζει λεπτομέρειες μόνο στον συνδεδεμένο πελάτη. Επιβεβαίωσε με τον πελάτη τον επιθυμητό τύπο ειδοποίησης και την άδεια επικοινωνίας. Η κατάσταση `queued` στο SMS.to δεν επιβεβαιώνει παράδοση.

## Ζ. Μετρήσεις και ασφάλεια

Η εφαρμογή αποθηκεύει ευαίσθητα δεδομένα υγείας. Μόνο ο αντίστοιχος συνδεδεμένος πελάτης έχει φόρμες καταχώρισης/διαγραφής και email export των δικών του μετρήσεων· ο admin έχει προβολή. Το export είναι **CSV ως συνημμένο email** με ρητή επιβεβαίωση παραλήπτη. Το τυπικό email **δεν εξασφαλίζει κρυπτογράφηση από άκρο σε άκρο**, επομένως πρέπει να αποστέλλεται μόνο σε ελεγμένο παραλήπτη, με επίγνωση κινδύνου. Συνιστάται για παραγωγή ασφαλέστερη λύση πρόσβασης/λήψης αρχείου μετά από ταυτοποίηση.

Πριν χρήση με πραγματικούς ασθενείς απαιτούνται έλεγχοι ασφάλειας, TLS, πολιτική διατήρησης/διαγραφής, ελάχιστα δικαιώματα, αντίγραφα ασφαλείας, προστασία πρόσβασης και αξιολόγηση GDPR. Μην εκθέτεις το development server στο δημόσιο Internet.
